Methodology and reproducibility

One machine, two timing scopes

Apple M1 Max, 64 GiB RAM, macOS 26.6.2 (25G83), 10 logical CPUs. OpenMP and numerical libraries default to one worker. Codon's Fannkuch explicitly requests four OpenMP threads; its parallel Primes loop uses the one-thread default. Native compilation and input preparation finished before the serial timing sweep.

Pyperformance and Applications retain their original timing boundaries. Each measurement uses a fresh process, so allocation and any PyPy JIT work inside the timer are included. One preliminary process is excluded. NPBench uses one process per implementation, one warm-up, then three kernel-only measurements; Numba specialization, input reset, and output serialization are excluded.

These are software-stack comparisons, not isolated compiler comparisons. Native Codon links Apple Accelerate; NumPy and Numba use the libraries recorded under Setup. Numba fast math is disabled in every kernel and helper. Codon is compiled without -fast-math. Other upstream Numba options are retained. Results describe this hardware and these inputs, not a universal ranking.

Numba was remeasured on 2026-11-08, using the original input hashes for 52 kernels. MLP was remeasured on all three runtimes: its previously unseeded input now uses NumPy legacy RNG seed 42, shared across runtimes; its seeded weights are unchanged. A separate histogram update on 2026-11-08 uses the uniform implementation on all three runtimes. All other Codon and Python timings are retained from the original sweep.

Memory and output checks

NPBench uses identical initialized inputs and persistent pristine/working arrays. Working arrays are reset in place, with garbage collection outside the timer. A separate reset audit checks allocation and address stability. Live-heap observations are retained in the raw report and do not determine whether completed timings are displayed.

NPBench output checks use upstream pointwise tolerances or a relative L2-error threshold, with exact integer checks. Application values are compared with CPython; Chaos uses an exact PPM check. Completed timings are included when outputs differ, with a brief note on the affected benchmark. Rounding and the order of floating-point operations can affect iterative calculations; the original check results remain available in the raw report.

The process timeout is 900 seconds, including warm-up and output writing. 1 incomplete implementation run has no reported timing; the diagnostics are retained in the raw report.

Source and inputs

Codon commit 14aaa30ab594; local binary and source fingerprints are included in the raw report. NPBench commit f2d7f27d87ba, always the largest standard L preset.

TAQ uses the first 10 million lines of EQY_US_ALL_NBBO_20220301. Word count uses 5.442 MiB of input-text.clean.txt, ending at a complete line. Dataset hashes and array dimensions are recorded; external input files are not redistributed.

The Numba MLP source corrects an upstream softmax maximum-axis error. Azimuthal histogram integration uses the same portable weighted-histogram helpers across Codon, Python, and Numba. Python interprets the weighted loop; unweighted counts use each runtime's np.histogram. Each implementation has three measured samples. Other compatibility adaptations are listed per implementation. Exact executed kernel/application sources and raw samples accompany the results.
